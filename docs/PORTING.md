# Порт на Windows и Linux

План переноса CommaEditor на Windows и Linux. Ветка `feature/cross-platform`. Общий план
разработки — [PLAN.md](PLAN.md), раздел «Windows и Linux».

## Что есть сейчас

- `core/comma-core` — всё, что делает редактор: парсинг, кодировки, правки, undo, сохранение,
  сортировка, фильтры, формулы, книги Excel. Чистый Rust, кода под конкретную ОС нет.
  Тонкие места — файловые операции (см. «Риски»).
- `core/comma-ffi` — фасад над ядром для приложения (≈2 400 строк): `CoreDocument`,
  `CoreWorkbook`, фоновые задачи `ViewJob`, `EditJob`, `SheetJob`, `DiffJob`, запись рецептов.
  Это обычный Rust-крейт (`crate-type` включает `lib`), UniFFI в нём — только атрибуты.
  Его можно подключить к Tauri напрямую, без второго слоя.
- `apps/macos` — интерфейс на AppKit (≈9 500 строк Swift без сгенерированных биндингов).
  Его нужно написать заново; переносится поведение, а не код.

## Решения

1. **Оболочка — Tauri 2**, как и записано в PLAN.md. Ядро и `comma-ffi` работают в процессе
   Tauri, интерфейс — в системном WebView (WebView2 на Windows, WebKitGTK на Linux).
2. **Своя сетка на canvas.** Готовые сетки не подходят: на 60 млн строк высота прокрутки
   выходит за пределы браузера (≈33 млн px в Chromium, меньше в WebKit). Значит, нужен свой
   виртуальный скроллбар, и строки рисуются только для видимого окна.
3. **API для оболочки — `comma-ffi`** с фичей `serde`: типы получают
   `#[cfg_attr(feature = "serde", derive(Serialize, Deserialize))]`, а Tauri-команды
   оборачивают методы `CoreDocument` и соседних типов. Логика остаётся в одном месте для обеих
   оболочек. Если атрибутов станет слишком много, фасад вынесем в отдельный крейт
   `comma-session`, а `comma-ffi` сделаем тонкой обёрткой.
4. **Фронтенд: TypeScript + Vite + Svelte 5.** Svelte — для панелей и окон, сетка — отдельный
   модуль без фреймворка.
5. **Две версии для macOS.** Основная — нативная на AppKit, как сейчас. Tauri-версия
   выходит и для macOS отдельным приложением с другим именем и bundle id
   (`app.commaeditor.Desktop`), чтобы обе можно было поставить рядом. Обе регистрируются
   для CSV и XLSX как `Alternate`, как и сейчас. Сборка под macOS — это ещё и основная
   площадка разработки.
6. **Без платных сертификатов.** Windows-сборка не подписывается, как и DMG сейчас
   (ad-hoc, без нотаризации). На сайте — инструкция, как пройти SmartScreen и Gatekeeper.
7. **Без автообновления.** Новая версия — по ссылке на сайте.

## Этапы

### 0. Ядро на трёх ОС

- [ ] `.gitattributes`: `-text` для `samples/**`, `qa/files/**`, `core/comma-core/tests/fixtures/**`
      и `*.csv`/`*.tsv`. Иначе Git на Windows с `core.autocrlf=true` заменит переводы строк, и
      побайтовые round-trip-тесты упадут на checkout, а не на коде.
- [ ] CI (GitHub Actions): `cargo test --workspace` и `cargo clippy` на `ubuntu-latest`,
      `windows-latest`, `macos-latest`. Закрывает и пункт «CI» из раздела «Инфраструктура».
- [ ] Прогнать `tests/large_files.rs::saves_over_a_file_mapped_from_disk` на Windows: это
      главный риск ядра (см. ниже). При ошибке — сохранение для Windows через переименование
      старого файла в сторону.
- [ ] `comma bench` на Windows и Linux — замерить, что скорость ядра та же.

**Готово, когда** CI зелёный на трёх ОС.

### 1. Проверка сетки (spike)

Самое рискованное делаем первым, до остального интерфейса.

- [ ] `apps/desktop/` — каркас Tauri 2: одно окно, открыть файл, показать сетку.
- [ ] Сетка на canvas: виртуальный скроллбар, видимое окно строк запрашивается одной командой
      (`visible_rows(start, count)`), HiDPI, светлая и тёмная тема.
- [ ] Передача строк: JSON, а если не хватит — бинарный ответ (`tauri::ipc::Response`).
- [ ] Замеры на файлах из `comma bench` (1, 12 и 60 млн строк) на Windows и Linux: первый экран,
      прокрутка, переход в конец.

**Готово, когда** прокрутка 60 млн строк плавная на обеих ОС, а первый экран — как в версии
для macOS. Если WebKitGTK не справится, сетку на Linux пересматриваем (рисование в Rust и вывод
в canvas картинкой, либо Slint/egui) до того, как писать остальное.

### 2. Основа приложения (уровень 0.1–0.4)

То, что на macOS даёт NSDocument, здесь делаем сами:

- [ ] Документ на окно: открыть, сохранить, «Сохранить как…» с форматом (0.3), признак
      изменений, вопрос при закрытии, недавние файлы.
- [ ] Окно параметров открытия и проверки кодировки (`preview_file`).
- [ ] Восстановление после сбоя вместо автосохранения на месте: черновик правок в папке
      данных приложения.
- [ ] Один экземпляр приложения: файл из Проводника или файлового менеджера открывается
      в уже запущенном (`tauri-plugin-single-instance`), перетаскивание файлов на окно.
- [ ] Правка ячеек, многострочный редактор, вставка и удаление строк и колонок, undo/redo.
- [ ] Выделение диапазонов, копирование и вставка в формате Excel: TSV и HTML в буфер обмена.
- [ ] Поиск и замена, сортировка, фильтры с фоновыми `ViewJob` (0.2), ход и отмена через
      `tauri::ipc::Channel`.
- [ ] Меню с сочетаниями клавиш для Windows и Linux (Ctrl вместо ⌘, F2, Ctrl+Y) и строка
      состояния.

**Готово, когда** чек-лист из `docs/RELEASE.md` для этих возможностей проходит на обеих ОС.

### 3. Инструменты (уровень 0.5–0.21)

Порядок примерно как на macOS; каждый пункт — UI поверх уже готового API в `comma-ffi`.

- [ ] Операции над колонками, экспорт и «Скопировать как» (0.5–0.6).
- [ ] Панель инструментов, иконки сортировки и фильтра в заголовках (0.7).
- [ ] Профиль колонки, ремонт файла, карточка записи (0.8–0.10).
- [ ] Вид таблицы: закрепление, ширина, скрытие, перенос, перемещение (0.11), невидимые

- [ ] Вычисляемая колонка (0.13), кодировки: открыть заново, кракозябры (0.14),

- [ ] Большие файлы: индексация в фоне с ходом, долгие правки с отменой (0.17–0.19).
- [ ] Сравнение двух файлов (0.20), рецепты (0.21) — в том же формате файлов, что на macOS,

### 4. Книги Excel (уровень 0.22–1.0)

- [ ] Листы, просмотр `.xlsx` и `.xls`, режимы «Таблица» и CSV.
- [ ] Правка, формулы, вставка и удаление строк и колонок, закрепление, оформление ячеек.

### 5. Выпуск

- [ ] Windows: установщик NSIS или MSI (сборщик Tauri), x64 и arm64, загрузчик WebView2,
      привязка `.csv`/`.tsv`/`.xlsx`. Без подписи: SmartScreen покажет «Windows защитила ваш
      компьютер» — на сайте объяснить «Подробнее ▸ Выполнить в любом случае» и дать SHA-256.
- [ ] Linux: AppImage и `.deb` (сборщик Tauri), Flatpak — отдельный манифест и Flathub;
      `.desktop`-файл с MIME-типами.
- [ ] macOS: универсальный DMG Tauri-версии с подписью ad-hoc, как у нативной;
      `xattr -dr com.apple.quarantine` из той же инструкции.
- [ ] Номер версии общий для всех сборок (`workspace.package.version`), в окне «О программе» —
      ссылка на страницу загрузки.
- [ ] `docs/RELEASE.md`: чек-лист ручной проверки для Windows, Linux и Tauri-версии на macOS;
      `site/` — страницы загрузки и объяснение, чем две версии для macOS отличаются.
- [ ] README и `Makefile`: `make desktop` и `make desktop-release`.

## Чего в Tauri-версии не будет сразу

Это касается и Tauri-версии для macOS: Quick Look, версии файлов и автосохранение на месте
остаются только у нативного приложения.

| В нативной версии для macOS | В Tauri-версии |
|---|---|
| Автосохранение на месте и версии (NSDocument) | Явное сохранение и восстановление после сбоя |
| Превью в Finder (Quick Look) | Позже: обработчик превью Проводника (COM-DLL на Rust) и миниатюры для Linux |
| Песочница App Store | Не нужна |
| VoiceOver | NVDA и Orca: ARIA-разметка для активной ячейки и панелей поверх canvas — с этапа 2, а не в конце |
| Отладочные сценарии `COMMA_DEBUG_SCRIPT` | Автотесты интерфейса через WebDriver (`tauri-driver` работает на Windows и Linux, на macOS нет — там тесты гоняем в CI на Linux) |
| Foundation Models, Spotlight (из «Ближайших шагов») | Не переносятся |

## Риски

- **Сохранение поверх файла, открытого через mmap (≥ 64 МБ), на Windows.** Ядро пишет
  временный файл и переименовывает его поверх исходного, а документ продолжает читать старые
  байты из отображения. На Unix это штатно. На Windows замена файла с активным отображением
  может завершиться отказом в доступе. Проверяется тестом
  `saves_over_a_file_mapped_from_disk` на этапе 0. Запасной вариант: переименовать исходный
  файл в сторону (это разрешено, `File::open` в Rust открывает с `FILE_SHARE_DELETE`),
  поставить новый на место, а старый удалить при закрытии документа.
- **Файл, занятый другой программой** (например, открыт в Excel): на Windows нельзя ни
  перезаписать, ни переименовать. Нужно понятное сообщение и «Сохранить как…».
- **Производительность WebKitGTK** на Linux — проверяется на этапе 1.
- **Атрибуты файла.** `write_atomically` переносит права исходного файла на новый. На Windows
  это только флаг «только чтение»; временный файл с точкой в начале имени там не скрыт.
  Проверить, что «только чтение» не мешает заменить файл.
- **Объём интерфейса.** Около 9 500 строк Swift превратятся в сопоставимый объём TS/Svelte,
  и две оболочки придётся поддерживать параллельно. Каждую новую фичу сначала добавляем в
  `comma-ffi`, тогда обе оболочки остаются тонкими.
- **Две версии для macOS путают.** Люди будут ставить не ту и спрашивать, почему нет
  Quick Look. Нужны разные имена (например, «CommaEditor» и «CommaEditor Desktop»), разные
  иконки или бейдж и строка на сайте, какую выбрать. Отложенный вариант — выпускать
  Tauri-версию для macOS как бету, пока она не догонит нативную.

## Структура

```
apps/
  macos/        как сейчас
  desktop/      Tauri 2: src-tauri/ (Rust, команды над comma-ffi), src/ (TS, Svelte, сетка)
core/
  comma-ffi/    + фича serde для Tauri
.github/workflows/ci.yml   тесты ядра на трёх ОС, сборка apps/desktop на Windows и Linux
```
